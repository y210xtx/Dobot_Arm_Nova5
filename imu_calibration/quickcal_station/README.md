# SDB QuickCal V1：11 路 IMU 机械臂标定站

这是从通用 Dobot 调试界面中拆出的专用 PySide6 工站界面。通信状态机、13 个正式阶段、
原始流、质量报告和异常恢复以《动捕手套工厂内参标定通信协议 V1.3 r024
无磁 QuickCal 原始流》为准；机械臂动作配置用于补充安全路径和实测旋转限位。

## 当前工作方式

- 同时连接 Dobot Nova 5（Dashboard 29999 / Feedback 30004）与手套 USB CDC。
- 只有机械臂实时状态、严格匹配的 r024 Type 8（revision 24、tag `r024-fac-rawq`、
  feature `0x20/0x40/0x80`）、SN、工位、G01/G02 配置轴限位，以及新鲜且 11/11 在线的
  `type=9/type=11` 原始流全部通过时，才能发送 `MCAL_BEGIN`。
- 机械臂动作采用监督执行：操作员或既有机器人程序完成表中动作；界面根据实际 TCP
  状态验证静止/匀速条件，然后开启对应 `MCAL_STAGE` 采集窗口。六面加速度计阶段还会
  根据 TCP 姿态计算重力在 Tool 坐标系中的方向：偏差超过 2°警告，超过 5°禁止采集。
- 当前动作出现速度偏离或阶段 ACK 异常时，界面先关闭当前阶段，然后停止机械臂并发送
  `MCAL_ABORT`；设备断线、机械臂报警、急停或提交失败也会放弃整轮。
- 全部动作通过后发送 `MCAL_COMMIT`，等待 ACK 和 `type=7`，然后保存原始数据、机器人
  反馈、阶段标记、矩阵报告及最终结果。

手套固件在内部采集 IMU 并求解标定参数；上位机同步接收 `type=9` 工程量和 `type=11`
寄存器原始量用于在线门控、板端阶段审计和失败诊断。两条流在空闲时应为 20 Hz、采集时
应为 100 Hz，龄期必须小于 800 ms，在线掩码必须为 `0x07FF`。采集期间还会核对帧内
`stageId/captureMask` 与当前阶段是否一致。任一条件不满足都会禁止开始或中止当前会话。

## Excel 工单中的动态阶段

当前采用 r024 无磁 QuickCal：正式阶段只有 P1、A01～A06、G01～G06。完成 G06 后机械臂
回到标定中位并确认静止，随后直接发送 `MCAL_COMMIT`；协议禁止发送 M01～M04。

- `G01/G02`：六面数据还原出的夹具 X 正/反向，对应 Tool `Rx+/-`；受该机械轴角度限制，完整行程固定为 `-55°～+55°`，匀速区固定为 `-45°～+45°`，采集固定 6 s。
- `G03/G04`：实测夹具 Y 正/反向，对应 Tool `Ry+/-`；完整行程为 `±85°`、匀速区为 `±75°`、采集固定 10 s。
- `G05/G06`：实测夹具 Z 正/反向，对应 Tool `Rz+/-`；完整行程为 `±85°`、匀速区为 `±75°`、采集固定 10 s。
- 任一正式阶段失败后发送 `MCAL_ABORT`，下一次必须从 `GET_VERSION/MCAL_BEGIN` 开始完整的新会话，不支持原会话内单段重试。
- P1 在会话建立后自动连续检查机械臂静止状态，满足 2 秒后自动开启 30 秒采集；机械臂反馈与 type=9 的 11 路陀螺幅值、加速度幅值和相邻帧变化共同参与静止门控。

## 机械臂动作自动化

“到标定中位”使用 30% 控制器速度比例（原 15% 的双倍）；“回安全位”仍保持 15%。

“开始全自动校准”采用一次启动的串行流程。点击后 P1 自动等待静止并采集，随后 A01～A06、G01～G06 依次执行；每一步只有在机械臂到位/速度门控、两条原始流审计、采集计时和固件阶段 ACK 均通过后才会启动下一步。G06 后直接自动提交，最终返回示教安全位并归档。全自动运行期间不再弹出逐步运动确认框；任一步预测、限位、碰撞、反馈、到位、原始流或固件检查失败都会停止机械臂并中止本次会话。

界面第 4 页“机械臂动作配置”集中保存 A01～A06、G01～G06 的自动动作参数。G 阶段可以分别配置实际 Tool 旋转轴，并通过有效扫转角的正负号配置方向；角度绝对值、15°/s 速度和采集时间由 r024 协议锁定：

- A01 默认根据首次实机日志及机械臂限位配置为当前 Tool `Rz +180.00°`、速度比例 5%；该旋转把重力的 Tool `-X` 分量翻转为 `+X`。速度允许配置为 1%～80%，本机修改后写入 `quickcal_actions.local.json`。
- A02 默认配置为当前 Tool `Rz -180.00°`，从 A01 的 `+X` 姿态沿原路径反向返回 `-X`，避免继续按同一方向累计旋转。
- A03 默认配置为当前 Tool `Rz +90.00°`，从 A02 的 `-X` 姿态旋转到 `+Y`。
- A04 默认配置为当前 Tool `Rz -180.00°`，从 A03 的 `+Y` 姿态旋转到 `-Y`，避免继续沿 Rz 正方向累计旋转。
- A05 默认配置为当前 Tool `Rx +90.00°`，从 A04 的 `-Y` 姿态旋转到 `+Z`。
- A06 默认配置为当前 Tool `Rx -180.00°`，从 A05 的 `+Z` 姿态旋转到 `-Z`，并减少 Rx 正方向的累计旋转。
- 进入 A01～A06 后点击对应的“自动旋转并执行”按钮，软件先显示当前偏差和旋转后的理论偏差；操作者确认安全后才发送 `RelMovLTool`。
- 相对角度大于 170°时拆成两个等角度控制器命令；XYZ 偏移保持为 0。
- 到位后重新使用机械臂实际反馈计算姿态，偏差不超过 5°并连续静止 2 s 才开启对应固件采集阶段；预测或实测不通过时不会开启采集。

G01 前只执行 Tool `Rx +90°` 撤销 A05/A06 的净姿态，从 `-Z` 回到 `-Y`。软件保持该 `-Y` 姿态作为 G01/G02 共用零位，使重力与受限 Tool `Rx` 垂直；随后预置到 `-55°`，在 `-55°→-45°` 加速，经过 `-45°` 且速度稳定在 `+15±3°/s` 时开启固定 6 秒采集。匀速采集覆盖 `-45°→+45°`，关闭采集后在 `+45°→+55°` 区间减速并回到 `-Y` 基准。

G02 与 G01 对称，使用 Tool `Rx` 反向扫转并回到同一 `-Y` 基准；G02 完成后才执行 Tool `Rz +90°` 回到全局 `-X` 标定中位，然后进入 G03。不得在 G01 前提前执行这一步 Rz 复原，否则重力会与 Rx 平行，G01/G02 将失去可用于陀螺求解的重力方向变化。

G03/G04 分别沿 Tool `Ry+`/`Ry-` 自动扫转；完整路径为 `-85°→+85°` / `+85°→-85°`。外侧 10° 是加减速区，仅在中间 ±75° 匀速段执行 10 秒采集。

G05/G06 分别沿 Tool `Rz+`/`Rz-` 自动扫转，完整路径为 `-85°→+85°` / `+85°→-85°`；只采集中间 `-75°～+75°` 匀速窗口。

G01～G06 点动速度均依据 `rotation_speed_calibration.json` 对应 Tool 轴的标定值计算。G01/G02 的 6 秒采集结束并发出阶段关闭命令后，会立即在 10°非采集区按七级 S 形比例逐步降低点动速度，不等待固件 ACK 消耗减速行程；若仍需小角度端点补偿，则使用 5% 加速度、15% 速度柔和到位。机械臂完全静止后才恢复进入该步骤前的全局速度比例，避免控制器在减速期间拒绝 `SpeedFactor`。每一步开始前都会核验当前姿态与示教标定中位，并保留速度、姿态、行程端点和碰撞状态保护。

Dobot `RobotMode=8` 表示点动/RunTo 单次运动，是 G01～G06 连续点动期间的正常动态状态；动态采集允许 `mode=7/8`。`mode=11` 表示碰撞检测触发，任何标定阶段收到该状态都会立即停止机械臂并中止固件会话。

## r024 诊断归档

每轮会话都会保存 `version_type8.bin/json`、`stage_markers.csv`、`cdc_bytes.csv`、
`raw_imu.csv`、`register_raw_imu.csv`、`robot_feedback.csv`、`mcal_ack.json`、
`mcal_report_type7.bin/json`、`raw_stream_diagnostics.json` 和 `final_summary.json`。
`type=7 v3` 会展开每一路 Gyro 的 `rejectFlags`、RMS、有效窗口数、最大交叉轴，以及
Accel 的残差、尺度误差、交叉轴和三轴偏置。即使 COMMIT 返回 status 5 或 11，上位机也会
继续等待并保存 type=7，避免只显示一个失败状态而丢失具体原因。

## Tool 坐标系与手动末端运动

界面第 5 页“Tool 与手动运动”可以配置并启用控制器 Tool 1～9，也可以切回法兰坐标系 Tool 0。Tool 参数顺序固定为 `X/Y/Z/Rx/Ry/Rz`：前三项是相对法兰坐标系的毫米偏移，后三项是角度偏移。保存时先调用 `SetTool` 写入控制器，再调用 `Tool` 启用，并同步保存到 `tool_offset_config.json`；本地配置不会在连接机械臂时未经确认自动写入控制器。

该页的坐标和角度控制使用 `MovL` 的绝对位姿模式，输入值是**当前 User 坐标系下的 TCP 绝对目标**，当前 Tool 补偿保持生效：

- 首次收到机械臂反馈时自动填入当前绝对位姿，也可点击“读取当前位姿”重新载入；
- “仅移动位置”采用输入的 `X/Y/Z`，并保留发送瞬间反馈的 `Rx/Ry/Rz`；
- “仅旋转姿态”采用输入的 `Rx/Ry/Rz`，并保留发送瞬间反馈的 `X/Y/Z`；
- 运动速度比例为 1%～80%，每次发送前都必须确认当前位姿、完整六维绝对目标和当前 User/Tool；
- 命令发送后持续跟踪机械臂反馈；连续静止 0.5 s 且位置误差不超过 2 mm、角度误差不超过 1°才显示完成，停止未到位、超时、报警、碰撞、反馈中断或 User/Tool 改变都会显示失败原因；
- 只允许在机械臂实时反馈新鲜、已使能、空闲且静止，并且标定会话未运行时操作。

## 启动

安装项目依赖后运行：

```powershell
python imu_calibration\quickcal_station_main.py
```

也可以双击项目根目录的 `run_quickcal_station.bat`。

## 重要限制

G01/G02 使用受限的 Tool `Rx`，工艺行程固定为 `-55°～+55°`，不允许在生产运行时扩大。工站使用前必须确认机械臂本体软限位、碰撞空间和线束余量能够覆盖该完整行程；修改任何 G 阶段轴或方向后必须先低速验证完整路径。

六面姿态门控以 Dobot 基座 `+Z` 向上、物理重力沿基座 `-Z` 为约定，并假定当前启用的
Tool 坐标系方向与标定夹具的 `X/Y/Z` 基准方向一致。如果 Tool 只定义了 TCP 平移位置、
方向没有与夹具对齐，必须先修正 Tool 定义，否则六面方向判定没有物理意义。
