# SDB QuickCal V1：11 路 IMU 机械臂标定站

这是从通用 Dobot 调试界面中拆出的专用 PySide6 工站界面。通信状态机、17 个正式阶段、
采集时间和异常恢复以《动捕手套工厂内参标定通信协议 V1.1 r022》为准；
`QuickCal_V1_Robot_Control_Steps_15dps.xlsx` 用于补充机械臂安全路径和 Yaw 限位。
若两者冲突，以 V1.1 通信协议为准。

## 当前工作方式

- 同时连接 Dobot Nova 5（Dashboard 29999 / Feedback 30004）与手套 USB CDC。
- 只有机械臂实时状态、兼容的 Type 8 版本/能力、SN、工位和 Yaw 限位全部通过时，
  才能发送 `MCAL_BEGIN`。`type=9/type=11` 是可选诊断流，不阻断标定。
- 机械臂动作采用监督执行：操作员或既有机器人程序完成表中动作；界面根据实际 TCP
  状态验证静止/匀速条件，然后开启对应 `MCAL_STAGE` 采集窗口。六面加速度计阶段还会
  根据 TCP 姿态计算重力在 Tool 坐标系中的方向：偏差超过 2°警告，超过 5°禁止采集。
- 当前动作出现速度偏离或阶段 ACK 异常时，界面先关闭当前阶段，然后停止机械臂并发送
  `MCAL_ABORT`；设备断线、机械臂报警、急停或提交失败也会放弃整轮。
- 全部动作通过后发送 `MCAL_COMMIT`，等待 ACK 和 `type=7`，然后保存原始数据、机器人
  反馈、阶段标记、矩阵报告及最终结果。

手套固件在内部采集 IMU 并求解标定参数，上位机收到的 `type=9` 工程量和 `type=11`
寄存器原始量不参与固件求解。固件若输出这些帧，工站仍会实时显示并在采集阶段分别写入
`raw_imu.csv` 和 `register_raw_imu.csv`；未输出时文件只有表头，不影响阶段 ACK 和最终报告。

## Excel 工单中的动态阶段

- `G01/G02`：X 轴 +15/-15 deg/s；`G03/G04`：Y 轴 +15/-15 deg/s；采样窗均为 10 s。
- `G05/G06`：Yaw +15/-15 deg/s，采样时间按实际软限位、安全余量和角速度计算（默认 5.333 s）。
- `M01`～`M04`：每段执行 15 s 缓慢三维翻转，四段使用互补路径扩大空间覆盖；四段均以 `captureMask=0x08` 正式采集。
- r022 不保证输出 type=12；该数据存在时只作为诊断记录，不作为 M 阶段开始或通过条件。
- 任一正式阶段失败后发送 `MCAL_ABORT`，下一次必须从 `GET_VERSION/MCAL_BEGIN` 开始完整的新会话，不支持原会话内单段重试。
- P1 在会话建立后自动连续检查机械臂静止状态，满足 2 秒后自动开启 30 秒采集，无需再次点击。若固件输出完整且新鲜的 type=9，软件还会联合检查 11 路陀螺幅值、加速度幅值和相邻帧变化；当前 r022 实机不输出 type=9 时，由机械臂门控开始阶段，并由固件阶段结束 ACK 的 11/11 质量门确认结果。

## 机械臂动作自动化

“到标定中位”使用 30% 控制器速度比例（原 15% 的双倍）；“回安全位”仍保持 15%。

界面第 4 页“机械臂动作配置”集中保存各步骤的自动动作参数。当前六面 A01～A06 均已启用，后续步骤仍为监督执行：

- A01 默认根据首次实机日志及机械臂限位配置为当前 Tool `Rz +180.00°`、速度比例 5%；该旋转把重力的 Tool `-X` 分量翻转为 `+X`。速度允许配置为 1%～80%，本机修改后写入 `quickcal_actions.local.json`。
- A02 默认配置为当前 Tool `Rz -180.00°`，从 A01 的 `+X` 姿态沿原路径反向返回 `-X`，避免继续按同一方向累计旋转。
- A03 默认配置为当前 Tool `Rz +90.00°`，从 A02 的 `-X` 姿态旋转到 `+Y`。
- A04 默认配置为当前 Tool `Rz -180.00°`，从 A03 的 `+Y` 姿态旋转到 `-Y`，避免继续沿 Rz 正方向累计旋转。
- A05 默认配置为当前 Tool `Rx +90.00°`，从 A04 的 `-Y` 姿态旋转到 `+Z`。
- A06 默认配置为当前 Tool `Rx -180.00°`，从 A05 的 `+Z` 姿态旋转到 `-Z`，并减少 Rx 正方向的累计旋转。
- 进入 A01～A06 后点击对应的“自动旋转并执行”按钮，软件先显示当前偏差和旋转后的理论偏差；操作者确认安全后才发送 `RelMovLTool`。
- 相对角度大于 170°时拆成两个等角度控制器命令；XYZ 偏移保持为 0。
- 到位后重新使用机械臂实际反馈计算姿态，偏差不超过 5°并连续静止 2 s 才开启对应固件采集阶段；预测或实测不通过时不会开启采集。
- G01 及以后动作要在实机验证六面动作的轴向、旋转方向、线束余量和碰撞空间后再逐步配置。

G01 已配置为自动动作：先执行 Tool `Rx +90°` 撤销 A05/A06 的净 Rx 姿态并恢复 A04 的 `-Y` 基准，随后预置到 `Rx -85°` 作为加速引入区。机械臂以 Tool `Rx+` 连续点动；当实测位置经过 `-75°` 且速度稳定在 `+15±3°/s` 时开启 10 秒采集，到达约 `+75°` 后停止，并自动回到本次 G01 的 X 中位。点动速度依据 `rotation_speed_calibration.json` 计算，结束后恢复进入 G01 前的全局速度比例。

Dobot `RobotMode=8` 表示点动/RunTo 单次运动，是 G01 连续点动期间的正常动态状态；动态采集允许 `mode=7/8`。`mode=11` 表示碰撞检测触发，任何标定阶段收到该状态都会立即停止机械臂并中止固件会话。

## Tool 坐标系与手动末端运动

界面第 5 页“Tool 与手动运动”可以配置并启用控制器 Tool 1～9，也可以切回法兰坐标系 Tool 0。Tool 参数顺序固定为 `X/Y/Z/Rx/Ry/Rz`：前三项是相对法兰坐标系的毫米偏移，后三项是角度偏移。保存时先调用 `SetTool` 写入控制器，再调用 `Tool` 启用，并同步保存到 `tool_offset_config.json`；本地配置不会在连接机械臂时未经确认自动写入控制器。

该页的坐标和角度控制使用 `MovL` 的绝对位姿模式，输入值是**当前 User 坐标系下的 TCP 绝对目标**，当前 Tool 补偿保持生效：

- 首次收到机械臂反馈时自动填入当前绝对位姿，也可点击“读取当前位姿”重新载入；
- “移动到绝对坐标”采用输入的 `X/Y/Z`，并保留发送瞬间反馈的 `Rx/Ry/Rz`；
- “旋转到绝对角度”采用输入的 `Rx/Ry/Rz`，并保留发送瞬间反馈的 `X/Y/Z`；
- 运动速度比例为 1%～80%，每次发送前都必须确认当前位姿、完整六维绝对目标和当前 User/Tool；
- 只允许在机械臂实时反馈新鲜、已使能、空闲且静止，并且标定会话未运行时操作。

## 启动

安装项目依赖后运行：

```powershell
python imu_calibration\quickcal_station_main.py
```

也可以双击项目根目录的 `run_quickcal_station.bat`。

## 重要限制

软件不会根据机械本体理论极限推测 Yaw 行程。工站使用前必须在“Yaw 限位与流程参数”页
填写控制器的实际软限位。当前版本不会自动生成六面和磁翻转轨迹；它负责联合通信、反馈
门控、阶段采集和结果追溯，机械臂动作由已验证的 Dobot 程序或示教轨迹执行。

六面姿态门控以 Dobot 基座 `+Z` 向上、物理重力沿基座 `-Z` 为约定，并假定当前启用的
Tool 坐标系方向与标定夹具的 `X/Y/Z` 基准方向一致。如果 Tool 只定义了 TCP 平移位置、
方向没有与夹具对齐，必须先修正 Tool 定义，否则六面方向判定没有物理意义。
